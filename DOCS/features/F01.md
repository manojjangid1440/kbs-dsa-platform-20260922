## Acceptance and failure cases

### F01.02a design and acceptance (before implementation)

Use an exact rolling window per organization and phone, canonical client IP and device identity. Hash IP/device identifiers with a separate server secret; store no raw identifiers in rate records. LOGIN and ADVISOR_SIGNUP share the same limits to prevent purpose switching. Limits/window lengths are required trusted configuration, never request fields. Acquire all three persistent scope locks in deterministic order, read database time after locking, and reserve all three allowances atomically. A rejected request charges none. Commit the reservation before any provider send; failed delivery does not refund the allowance. Trusted socket/proxy resolution and delivery orchestration remain required before exposing a live route. Device identity is an additional abuse signal, not a substitute for phone/IP limits. Test each dimension, cross-organization isolation, equivalent IP forms, expiry, restart persistence and concurrent requests at the limit. Retention/cleanup requires approved policy; no silent deletion is introduced.

AUTH-01/02; invalid/expired/reused code fails, re-login never resets training; client cannot select role; blocked account rejected; generic enumeration-safe errors.

Test authorized happy path, wrong-role/wrong-object access, repeated request, missing configuration and interrupted request. Relevant source acceptance IDs remain in testing/source-acceptance.md.
